## 概述

本文档介绍 **BrixelAI**（Scratch 3.0 的分支版本）中新增或改进的扩展积木。

> 📊 **规模（2026-08-07 实测）:** 扩展文件夹 **105** 个 · 在 `extension-manager` 中注册 **98** 个 · GUI 扩展卡片 **96** 个
> （包含标准 Scratch 内置扩展。文件夹数多于注册数，是因为已废弃／暂缓的扩展仍以文件夹形式保留。）
>
> ⚠️ **这些数字还会继续增加。** 引用之前请自行清点:
> ```bash
> cd scratch-editor/packages/scratch-vm/src/extensions && ls -d scratch3_*/ | wc -l
> ```
> 下方「完整扩展列表」表格可能因最后修订时间不同而落后于实际数量。

**扩展构成:**

* ✨ **新增:** IoT 与实时模式硬件板、AI、计算机视觉、MLOps 流水线、数据科学、TTS 等
* ⭐ **现有改进:** Pen、Translate、Video Sensing
* 🔌 **实时模式硬件板 (v1.6):** Rich Shield、Mega SuperRich、micro:bit V2 + ma:bit、ESP32 全套件 —— 通过串口／蓝牙实时控制真实板卡（固件调度器模式）
* 📷 **手机摄像头 (v1.6):** 通过 WebRTC P2P 将手机摄像头注入舞台 —— 可与所有 AI 视觉扩展配合使用
* 🧩 **MLOps 流水线 (v1.6):** 8 个阶段的端到端 ML 工作流（数据 → 媒体 → AutoML → 神经网络构建器 → 实验追踪 → 评估 → 负责任 AI → 模型中心）

## IoT 与硬件通信

### 1. Web Serial

**主要技术:** Web Serial API

**功能:**

* 与 Arduino, Micro:bit 等串口设备进行有线通信。
* 发送模式: 发送一次, 连续发送, 以“名称:值”格式发送。
* 接收模式: 按换行符解析, 按逗号解析。
* 波特率设置 (9600 ~ 115200 baud)。
* 防止重复数据发送, 节流 (Throttling, 30ms)。

**主要积木:**

* `连接 Web Serial`
* `发送 [TEXT] 一次 (带换行)`
* `连续发送 [TEXT]`
* `接收到的数据 (读取一行)`
* `用 [DELIMITER] 分割接收到的数据`

**使用示例:**

```
连接 Web Serial
将波特率设置为 115200
发送 LED:ON 一次 (带换行)

```

---

### 2. Web Bluetooth

**主要技术:** Web Bluetooth API (BLE)

**功能:**

* 与 Micro:bit, Arduino, ESP32 等蓝牙设备进行无线通信。
* 自动识别设备类型 (Nordic UART, JDY-33, HM-10)。
* 20 字节分块传输 (支持 BLE MTU)。
* 发送/接收协议与 Web Serial 相同。

**主要积木:**

* `连接到 [DEVICE_TYPE] 设备 (默认)`
* `连接设备 服务UUID [SERVICE] TX [TX] RX [RX]`
* `蓝牙是否已连接？`
* `连续发送 名称 [LABEL] : 值 [VALUE]`

**支持设备:**

* BBC micro:bit
* Arduino/ESP32 (Nordic UART)
* JDY-33/HM-10 (AT 模式)
* 所有其他 BLE 设备 (自动检测)

---

### 3. WiFi (WebSocket)

**主要技术:** WebSocket (ws:// / wss://)

**功能:**

* 与 ESP8266, ESP32 等 WiFi 设备进行 WebSocket 通信。
* 自动选择协议 (HTTPS 环境下使用 wss://)。
* 流模式: 原始数据 (Raw) 传输, CSV 多重传输, 标签:值 传输。
* 节流 (Throttling) 50ms (比 Web Serial 更快)。

**主要积木:**

* `连接到位于 [IP]:[PORT] 的 WiFi 设备`
* `安全连接 [PROTOCOL] [ADDRESS]`
* `连续发送 [DATA] (Raw) (无换行)`
* `连续发送 [NUM_FIELDS] 个变量: [DATA]`

**使用示例:**

```
连接到位于 192.168.1.10:8080 的 WiFi 设备
连续发送 3 个变量: 100, 200, 300

```

### 4a. 实时模式硬件板 ⭐ NEW (v1.6)

四种实物板卡可通过 USB 串口和/或蓝牙 (BLE) 从 BrixelAI **实时**控制。板卡运行轻量级的**固件命令调度器**；所有逻辑都保留在 Scratch VM 中 (文本行协议, 以 `\n` 结尾)。固件可直接从扩展中烧录/下载。

| 板卡 | EXT ID | 接线方式 | 固件 | 烧录方式 |
| --- | --- | --- | --- | --- |
| **Rich Shield (Uno)** | `richshield` | 子板, 固定引脚 | Arduino (实时调度器) | Web Serial 烧录 |
| **Mega SuperRich** | `superrich` | 每个设备固定引脚 | Arduino (实时调度器) | Web Serial 烧录 |
| **micro:bit V2 + ma:bit** | `microbitv2` | 扩展板, 固定引脚 | MakeCode (TypeScript) | 将 hex 拖入 MICROBIT 磁盘 |
| **ESP32 全套件** | `esp32fullset` | 自由接线 (引脚参数) | Arduino-ESP32 | esptool-js 自动烧录 |

**通用功能:**

* **双通道:** 可通过 USB 串口 (有线) 或蓝牙 BLE (无线) 连接 — 两者使用相同协议。
* **固件版本报告积木** + 连接时自动握手 (HELLO/CAPS)。
* 每块板卡都具备完整的 I/O 支持: 舵机, NeoPixel, RGB LED, 风扇/电机, 蜂鸣器/扬声器, LCD/OLED, 点阵屏, 超声波, 各类传感器等。
* **micro:bit V2 专有功能:** NeoPixel 灯珠数量设置, MakeCode 音符, 帽子事件 (按钮/手势/声音/logo/引脚), 指南针校准保护。BLE 使用 micro:bit 的 NUS 变体 (TX = indicate, 通过特征属性自动检测)。
* **ESP32 全套件专有功能:** 使用引脚编号参数自由接线 (而非固定引脚), 每位学生独立的 BLE 名称 (NVS), 带点击输入网格的 8×8/8×16 点阵屏, 滚动文字, 蜂鸣器音符/节拍菜单。
* **SuperRich/Rich Shield 专有功能:** 通过下拉菜单实现的单个合并式 MP3 积木 (停止/暂停/继续/下一首/上一首/循环/音量±)。

**使用示例 (ESP32 全套件):**

```
连接 ESP32 (USB)
舵机 引脚 32 角度 90
NeoPixel 引脚 18 全部设为 R 255 G 0 B 0
距离(cm) trig 5 echo 18
```

### 4b. 手机摄像头 ⭐ NEW (v1.6)

**主要技术:** WebRTC P2P + 本地桥接 + 二维码配对

**功能:**

* 将**手机摄像头**作为视频源接入 Scratch 舞台。
* 用手机扫描电脑屏幕上的二维码 → 建立 WebRTC 点对点连接 (每位学生独立的房间 ID)。
* **自动适用于所有 AI 视觉扩展** — 人脸/手部/姿态/物体识别、图像分类器等都会使用手机画面而非网络摄像头 (通过共享的 `runtime.ioDevices.video` 提供器 + CameraManager 同步)。
* 完全分布式: 每位学生的手机只连接到自己的笔记本电脑 (1:1, 无中央服务器) — 适用于 30 人班级。

**主要积木:**

* `连接手机摄像头 (显示二维码)`
* `断开手机摄像头`
* `< 手机已连接？ >`
* `关闭二维码` / `连接状态`

```

### 8. 语音识别 (Speech Recognition)

**主要技术:** Web Speech API

**功能:**

* 实时语音转文本 (Speech-to-Text)。
* 命令检测 (前进, 后退, 左, 右, 停止, 走, 转弯)。
* 数值参数提取 (速度, 角度, 距离)。
* 多语言支持 (韩语, 英语, 日语, 中文等)。
* 情感分析 (积极/消极/中性)。

**主要积木:**

* `将语言设置为 [LANG]`
* `开始语音识别`
* `识别到的文本`
* `最后的命令`

### 28. 翻译 (Translate)

#### 多代理故障转移策略 (Multi-Proxy Failover Strategy)

**问题:**

* 以前: 使用单个代理 → 如果该代理宕机，翻译失败。
* 由于 CORS 策略，无法直接访问。

**解决方案:**

* 按顺序尝试 3 个 CORS 代理。
* 快速失败策略 (每个代理超时 4 秒)。
* 如果一个失败，自动尝试下一个代理。

**代理顺序:**

1. **corsproxy.io** - 最快 (首选尝试)
2. **allorigins.win** - 稳定 (次级备份)
3. **codetabs.com** - 最终备份

**主要积木:**

* `将 [WORDS] 翻译为 [LANGUAGE]` - 翻译文本 (稳定性提高)。
* `语言` - 当前项目语言。

**改进:**

* ✅ 消除了单点故障。
* ✅ 显著提高了翻译成功率。
* ✅ 对代理宕机具有鲁棒性。
* ✅ 自动缓存 (对相同文本/语言的重复请求立即返回)。

**使用示例:**

```
翻译结果 = 将 [你好] 翻译为 [英语]
// 结果: "Hello"

翻译结果 = 将 [Hello] 翻译为 [日语]
// 结果: "こんにちは"

```

**支持语言:**
支持超过 100 种语言 (韩语, 英语, 日语, 中文, 法语, 西班牙语等)。

## MLOps 流水线 ⭐ NEW (v1.6)

8 个阶段的端到端机器学习工作流，使 BrixelAI 成为教授完整机器学习生命周期的教学平台。每个阶段都是一个独立的扩展；它们通过共享的 `runtime.brixelMLState` (当前数据集、当前模型、实验记录、已部署模型) 互相通信。

| 阶段 | EXT ID | 作用 |
| --- | --- | --- |
| **1. 数据流水线** | `datapipeline` | 构建/清洗表格数据集、导入 CSV、特征列 |
| **2. 媒体流水线** | `mediapipeline` | 从摄像头或文件构建图像/音频/人脸/手部/姿态数据集 |
| **3. AutoML** | `automl` | 在数据集上自动选择模型并训练 |
| **4. 神经网络构建器** | `nnbuilder` | 逐层设计神经网络架构 |
| **5. 实验追踪** | `exptracking` | 记录运行、超参数与指标以供比较 |
| **6. 模型评估** | `modeleval` | 通过 `model.predict()` 计算准确率、混淆矩阵、各类别指标 |
| **7. 负责任的 AI** | `responsibleai` | 跨群体的公平性/偏见检查 |
| **8. 模型中心 (Model Hub)** | `modelhub` | 共享/下载已训练模型 (Firebase)、轻量 JSON 序列化 |

**流程:** 媒体/数据流水线 → 训练 (AutoML / 神经网络构建器 / 某个训练扩展) → `将模型提升到流水线` → 评估 → 负责任的 AI → 发布到模型中心。训练类扩展 (图像/声音/文本模型、KNN、SVM 等) 通过把训练好的模型提升为 `currentModel` 接入这条流水线。

> 注意: 模型中心仅序列化模型权重/特征 (上传时会剥离缩略图和体积较大的原始媒体，以保持共享模型体积小巧)。
