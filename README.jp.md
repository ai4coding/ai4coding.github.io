## 概要

本ドキュメントでは、**BrixelAI**（Scratch 3.0 のフォーク）に新しく追加、または改善された拡張機能ブロックについて説明します。

> 📊 **規模（2026-08-07 実測）:** 拡張機能フォルダ **105個** · `extension-manager` への登録 **98個** · GUI 拡張機能カード **96個**
> （標準の Scratch 内蔵拡張機能を含みます。フォルダ数が登録数より多いのは、廃止・保留中の拡張機能がフォルダとして残っているためです。）
>
> ⚠️ **この数値は増え続けます。** 引用する前に、ご自身で数えて確認してください:
> ```bash
> cd scratch-editor/packages/scratch-vm/src/extensions && ls -d scratch3_*/ | wc -l
> ```
> 下の「全拡張機能リスト」の表は、最後に改訂した時期によっては実際の数より少ない場合があります。

**拡張機能の構成:**

* ✨ **新規追加:** IoT & ライブモード対応ハードウェアボード、AI、コンピュータビジョン、MLOps パイプライン、データサイエンス、TTS など
* ⭐ **既存の改善:** Pen、Translate、Video Sensing
* 🔌 **ライブモード対応ハードウェアボード (v1.6):** Rich Shield、Mega SuperRich、micro:bit V2 + ma:bit、ESP32 フルキット — シリアル／Bluetooth 経由で実機のボードをライブ制御します（ファームウェアディスパッチャ方式）
* 📷 **スマートフォンカメラ (v1.6):** WebRTC P2P でスマートフォンのカメラをステージに取り込みます — すべての AI ビジョン拡張機能と連携します
* 🧩 **MLOps パイプライン (v1.6):** 8段階のエンドツーエンド ML ワークフロー（データ → メディア → AutoML → ニューラルネットビルダー → 実験トラッキング → 評価 → 責任ある AI → モデルハブ）

## IoT & ハードウェア通信

### 1. Webシリアル (Web Serial)

**主要技術:** Web Serial API

**機能:**

* Arduino, Micro:bit などのシリアルデバイスと有線通信します。
* 送信モード: 1回送信, 連続送信, 「名前:値」形式での送信に対応します。
* 受信モード: 改行区切りでの解析, カンマ区切りでの解析に対応します。
* 通信速度を設定できます (9600 ~ 115200 baud)。
* 重複データの送信を防止し, スロットリング (30ms) を行います。

**主要ブロック:**

* `Webシリアルを接続する`
* `[TEXT] を1回送信する (改行あり)`
* `[TEXT] を連続送信する`
* `受信データ (1行読む)`
* `受信データを [DELIMITER] で分割する`

**使用例:**

```
Webシリアルを接続する
通信速度を 115200 に設定する
LED:ON を1回送信する (改行あり)

```

---

### 2. Web Bluetooth

**主要技術:** Web Bluetooth API (BLE)

**機能:**

* Micro:bit, Arduino, ESP32 などの Bluetooth デバイスと無線通信します。
* デバイスタイプを自動認識します (Nordic UART, JDY-33, HM-10)。
* 20バイトごとのチャンク分割送信を行います (BLE MTU 対応)。
* 送受信プロトコルは Webシリアルと同一です。

**主要ブロック:**

* `[DEVICE_TYPE] デバイスに接続する (基本)`
* `サービスUUID [SERVICE] TX [TX] RX [RX] でデバイスに接続する`
* `Bluetoothは接続されているか？`
* `名前 [LABEL] : 値 [VALUE] を連続送信する`

**対応デバイス:**

* BBC micro:bit
* Arduino/ESP32 (Nordic UART)
* JDY-33/HM-10 (AT Mode)
* その他すべてのBLEデバイス (自動検出)

### 3. Wi-Fi (WebSocket)

**主要技術:** WebSocket (ws:// / wss://)

**機能:**

* ESP8266, ESP32 などの Wi-Fi デバイスと WebSocket 通信します。
* プロトコルを自動選択します (HTTPS環境では wss://)。
* ストリーミングモード: Raw送信, CSV多重送信, 「ラベル:値」送信に対応します。
* スロットリング 50ms (Webシリアルより高速)。

**主要ブロック:**

* `[IP]:[PORT] のWi-Fiデバイスに接続する`
* `[PROTOCOL] [ADDRESS] にセキュア接続する`
* `[DATA] (Raw) を連続送信する (改行なし)`
* `[NUM_FIELDS]個の変数を連続送信する: [DATA]`

**使用例:**

```
192.168.1.10:8080 のWi-Fiデバイスに接続する
3個の変数を連続送信する: 100, 200, 300

```

### 4. ESP32-CAM ビデオ

**主要技術:** WebSocket + Python ブリッジ

* `ESP32-CAM スナップショットを保存する`

### 4a. ライブモード対応ハードウェアボード ⭐ NEW (v1.6)

4種類の実機ボードを, USBシリアルおよび Bluetooth (BLE) 経由で BrixelAI から**ライブ**に制御できます。ボード側は軽量な**ファームウェアコマンドディスパッチャ**を動かすだけで, すべてのロジックは Scratch VM 側にとどまります (テキスト行プロトコル, `\n` 終端)。ファームウェアは拡張機能から直接書き込み/ダウンロードできます。

| ボード | EXT ID | 配線モデル | ファームウェア | 書き込み方法 |
| --- | --- | --- | --- | --- |
| **Rich Shield (Uno)** | `richshield` | シスターボード, ピン固定 | Arduino (ライブディスパッチャ) | Web Serial 書き込み |
| **Mega SuperRich** | `superrich` | デバイスごとにピン固定 | Arduino (ライブディスパッチャ) | Web Serial 書き込み |
| **micro:bit V2 + ma:bit** | `microbitv2` | シールド, ピン固定 | MakeCode (TypeScript) | hex を MICROBIT ドライブにドラッグ |
| **ESP32 フルキット** | `esp32fullset` | 自由配線 (ピン番号を引数で指定) | Arduino-ESP32 | esptool-js 自動書き込み |

**共通機能:**

* **デュアルチャネル:** USBシリアル (有線) または Bluetooth BLE (無線) で接続でき, どちらも同じプロトコルです。
* **ファームウェアバージョンの値ブロック** + 接続時の自動ハンドシェイク (HELLO/CAPS)。
* ボードごとに完全な I/O スタックを備えています: サーボ, NeoPixel, RGB LED, ファン/モーター, ブザー/スピーカー, LCD/OLED, ドットマトリクス, 超音波, 各種センサーなど。
* **micro:bit V2 固有:** NeoPixel の LED 個数設定, MakeCode の音符, ハットイベント (ボタン/ジェスチャー/音/ロゴ/ピン), コンパス較正ガード。BLE は micro:bit 独自の NUS 変種を使用します (TX = indicate, キャラクタリスティックのプロパティで自動検出)。
* **ESP32 フルキット固有:** ピン固定ではなくピン番号を引数で指定する自由配線, 生徒ごとの BLE 名 (NVS), クリック入力グリッド付き 8×8/8×16 ドットマトリクス, スクロールテキスト, ブザーの音符/拍メニュー。
* **SuperRich/Rich Shield 固有:** ドロップダウンメニューで操作を選ぶ統合 MP3 ブロック1個 (停止/一時停止/再開/次/前/リピート/音量±)。

**使用例 (ESP32 フルキット):**

```
ESP32 に接続する (USB)
サーボ ピン 32 角度 90
NeoPixel ピン 18 全体を R 255 G 0 B 0 にする
距離(cm) trig 5 echo 18
```

### 4b. スマートフォンカメラ ⭐ NEW (v1.6)

**主要技術:** WebRTC P2P + ローカルブリッジ + QRペアリング

**機能:**

* **スマートフォンのカメラ**を映像ソースとして Scratch のステージに取り込みます。
* パソコンの画面に表示された QR コードをスマートフォンで読み取ると, WebRTC のピアツーピア接続が確立します (生徒ごとのルームID)。
* **すべてのAIビジョン拡張機能で自動的に利用できます** — 顔/手/ポーズ/物体認識, 画像分類などが Webカメラの代わりにスマートフォンの映像を使用します (共有の `runtime.ioDevices.video` プロバイダ + CameraManager 同期による)。
* 完全分散型: 各生徒のスマートフォンは自分のノートパソコンにのみ接続します (1:1, 中央サーバー不要) — 30人規模の教室でも安心です。

**主要ブロック:**

* `スマートフォンカメラを接続する (QRを表示)`
* `スマートフォンカメラを切断する`
* `< スマートフォンは接続されているか？ >`
* `QRを閉じる` / `接続状態`

## AI & 機械学習

### 5. Teachable Machine 画像

**主要技術:** Teachable Machine Image Model

**機能:**

* Google Teachable Machine で学習した画像分類モデルを使用します。
* モデルURLを入力してカスタム分類器をロードします。
* 閾値設定 (0.0 ~ 1.0) で認識精度を調整します。

**主要ブロック:**

* `Teachable Machine サイトへ行く`
* `モデルのアドレスを [URL] に変更する`
* `閾値を [THRESHOLD] に変更する`
* `モデルを開始する`
* `認識結果`

**使用例:**

```
モデルのアドレスを https://teachablemachine.withgoogle.com/models/ABC123/ に変更する
閾値を 0.8 に変更する
モデルを開始する
もし (認識結果) = [猫] ならば
  「猫を発見！」と言う

```

**主要技術:** Teachable Machine Pose Model

**機能:**

* 身体ポーズに基づいて分類します (例: 手を挙げる, 座る, 立つ)。

### 28. 翻訳 (Translate)

**主要技術:** Google Translate API + Multi-Proxy

**既存機能:**

* テキストを様々な言語に翻訳します。
* 現在のプロジェクト言語を検出します。

**⭐ 新規追加機能:**

#### マルチプロキシ フェイルオーバー戦略 (Multi-Proxy Failover Strategy)

**問題点:**

* 従来: 単一プロキシを使用 → そのプロキシがダウンすると翻訳できません。
* CORSポリシーにより直接アクセスできません。

**解決策:**

* 3つのCORSプロキシを順次試行します。
* ファストフェイル戦略 (各プロキシ4秒タイムアウト)。
* 1つが失敗すると自動的に次のプロキシを試行します。

**プロキシ順序:**

1. **corsproxy.io** - 最速 (優先試行)
2. **allorigins.win** - 安定 (2次バックアップ)
3. **codetabs.com** - 最終バックアップ

**主要ブロック:**

* `[WORDS] を [LANGUAGE] に翻訳する` - テキストを翻訳します (安定性向上)。
* `言語` - 現在のプロジェクト言語。

**改善事項:**

* ✅ 単一障害点 (Single Point of Failure) の排除。
* ✅ 翻訳成功率の大幅な向上。
* ✅ プロキシのダウンタイムに対する堅牢性。
* ✅ 自動キャッシング (同一テキスト/言語の繰り返しリクエスト時は即時返却)。

**使用例:**

```
翻訳結果 = translate [こんにちは] to [English]
// 結果: "Hello"

翻訳結果 = translate [Hello] to [Japanese]
// 結果: "こんにちは"

```

**対応言語:**
100以上の言語に対応しています (韓国語, 英語, 日本語, 中国語, フランス語, スペイン語など)。

## MLOps パイプライン ⭐ NEW (v1.6)

BrixelAI を ML ライフサイクル全体の教育プラットフォームに変える、8段階のエンドツーエンド機械学習ワークフローです。各段階はそれぞれ独立した拡張機能で、共有の `runtime.brixelMLState` (現在のデータセット、現在のモデル、実験、デプロイ済みモデル) を通じて連携します。

| 段階 | EXT ID | 役割 |
| --- | --- | --- |
| **1. データパイプライン** | `datapipeline` | 表形式データセットの構築・クレンジング、CSV読み込み、特徴量列 |
| **2. メディアパイプライン** | `mediapipeline` | カメラやファイルから画像/音声/顔/手/ポーズのデータセットを構築 |
| **3. AutoML** | `automl` | データセットに対するモデルの自動選択と学習 |
| **4. ニューラルネットビルダー** | `nnbuilder` | ニューラルネットワークの構造をレイヤーごとに設計 |
| **5. 実験トラッキング** | `exptracking` | 実行・ハイパーパラメータ・指標を記録して比較 |
| **6. モデル評価** | `modeleval` | `model.predict()` による正解率、混同行列、クラス別指標 |
| **7. 責任あるAI** | `responsibleai` | グループ間の公平性/バイアスの点検 |
| **8. モデルハブ** | `modelhub` | 学習済みモデルの共有/ダウンロード (Firebase)、軽量なJSONシリアライズ |

**フロー:** メディア/データパイプライン → 学習 (AutoML / ニューラルネットビルダー / 各学習拡張機能) → `モデルをパイプラインに昇格させる` → 評価 → 責任あるAI → モデルハブへ公開。学習系の拡張機能 (画像/音声/テキストモデル、KNN、SVM など) は、学習済みモデルを `currentModel` に昇格させることでこのパイプラインに接続します。

> 注: モデルハブはモデルの重み/特徴量のみをシリアライズします (共有モデルを小さく保つため、サムネイルや容量の大きい生メディアはアップロード時に取り除かれます)。

### v1.6 (2026-06-05)
- 🔌 **ライブモード対応ハードウェアボードの追加** (新規) — シリアル/Bluetooth で実機ボードをライブ制御
  - Rich Shield (Uno) `richshield`、Mega SuperRich `superrich`
  - micro:bit V2 + ma:bit シールド `microbitv2` (MakeCode ファームウェア、hex ドラッグで書き込み)
  - ESP32 フルキット `esp32fullset` (ピン番号を引数にした自由配線、esptool-js による自動書き込み)
  - ファームウェアディスパッチャ方式: ボード = コマンド実行器、Scratch VM = ロジック
  - デュアルチャネル (USBシリアル + BLE)、ファームウェアバージョンのレポーター、自動ハンドシェイク
- 📷 **スマートフォンカメラ拡張機能の追加** (新規) `phonecam`
  - WebRTC P2P でスマートフォンのカメラをステージに取り込み (QRペアリング、生徒ごとのルーム)
  - すべてのAIビジョン拡張機能と自動的に連携 (共有ビデオプロバイダ + CameraManager)
  - 完全分散型 (1:1 スマートフォン↔ノートPC) — 30人学級でも安心
- 🧩 **MLOps パイプラインの追加** (新規) — 8段階のエンドツーエンド ML ワークフロー
  - `datapipeline` → `mediapipeline` → `automl` → `nnbuilder` → `exptracking` → `modeleval` → `responsibleai` → `modelhub`
  - 共有の `runtime.brixelMLState`。学習系拡張機能がモデルをパイプラインに昇格
- 🖼️ **画像分類モデル — クラスギャラリー** (新規)
  - `クラス画像ギャラリーを表示する` ブロック: クラスごとに画像を閲覧 (96×96 サムネイル、原寸モーダル、JPG ダウンロード)
  - モデルハブへのアップロード時はサムネイルを除去して共有モデルを軽量化
- 🤖 **AI拡張機能の拡充** — 顔 (特徴/識別/表情)、手 (特徴/ジェスチャー)、ポーズ (特徴/学習)、ボディセグメンテーション、オブジェクトトラッキング、カラー領域、人物追従、6軸ロボットアーム、QR/バーコード、ARタグ、地図ビューア、Google Gemini、ローカルLLM、IFTTT、BrixelAI アシスタント
- 🔧 **micro:bit V2 ファームウェアの安定化 (fw v0.7.x)**
  - NeoPixel LED個数ブロック、MakeCode 音符 (P0競合ガード)、ハットイベント、コンパス較正ガード
  - ファンPWM 1 kHz 修正 + 方向メニュー、BLE NUS indicate 自動判定 (TX/RX 入れ替わり対応)
- 全拡張機能数: 45 → 79 (Scratch標準の組み込み拡張機能を含む)
